# AD QUEST — Standalone Deploy (Render Free + Neon Free)

Platform ujian sekolah dengan empat role — **Admin, Guru, Pengawas, Siswa** —
login satu kolom Key (role dikenali server dari Key), pembuat soal manual &
dibantu AI, ujian online dengan timer dan kunci otomatis anti-pindah-aplikasi,
pantauan Pengawas dengan notifikasi akun terkunci, dan Kotak Masuk Hasil
dengan penilaian essay. Nilai **tidak pernah** ditampilkan ke siswa.

This is the standalone port of the AD QUEST Muse web artifact: same client
UI and same action logic, re-hosted on plain **Express + Postgres (Drizzle)**
so it can run anywhere — configured here for **Render Free** (app) +
**Neon Free** (Postgres), region **Singapore**.

## Stack

- Client: React 19 + Vite + Tailwind CSS 4 (`client/`)
- Server: Express 5, one RPC endpoint `POST /actions {action, args}` (`server/`)
- DB: Postgres via Drizzle ORM; schema in `server/src/schema.ts`, SQL in
  `db/0001_initial.sql` (applied automatically on every server boot —
  idempotent `CREATE TABLE IF NOT EXISTS`)
- AI questions: external OpenAI-compatible API **only if** `AI_API_KEY` is
  set; otherwise a built-in local template generator builds drafts from the
  teacher's material (cloze/comprehension/arithmetic), so the feature never
  dead-ends and costs nothing.

## Environment variables

| Key | Required | Notes |
| --- | --- | --- |
| `DATABASE_URL` | ✅ | Neon connection string. Set it **only** in the host's env settings — never commit it. |
| `ADMIN_KEY` | ✅ (first boot) | Becomes the **first Admin's login Key**, created only while the users table is empty. No self-registration exists. Choose a long random value. Changing it later does **not** rotate the live key. |
| `ADMIN_NAME` | – | Display name of the seeded Admin (default `Admin`). |
| `AI_API_KEY` | – | Optional external AI. Empty = local generator. |
| `AI_API_BASE_URL` | – | Default `https://api.openai.com/v1` (any OpenAI-compatible endpoint). |
| `AI_MODEL` | – | Default `gpt-4o-mini`. |
| `PORT` | – | Set automatically by Render. Default `3000`. |

There are **no hardcoded keys or secrets anywhere in this repo**
(`.env.example` contains placeholders only).

## Deploy — exact steps for the owner

### 1. Neon (database) — already created? You need the connection string
1. Open <https://console.neon.tech> → your **AD Quest** project (branch `production`).
2. Click **Connect** → **Connection string** → copy the full
   `postgresql://…neon.tech/…?sslmode=require` string.
3. Keep it somewhere private for step 3. **Do not** paste it into git,
   GitHub, or a chat — it contains the database password.

### 2. GitHub (code)
```bash
cd ad-quest-deploy
git init        # (already initialized if you received this repo as a git repo)
git add .
git commit -m "AD QUEST standalone deploy"
git branch -M main
git remote add origin https://github.com/<your-username>/ad-quest.git
git push -u origin main
```
(Create the empty `ad-quest` repository first at <https://github.com/new> —
do **not** add a README there; this repo already has one. `.gitignore`
already excludes `.env`, `node_modules/`, and build output.)

### 3. Render (app)
1. Open <https://dashboard.render.com> → **New** → **Blueprint** → connect
   the `ad-quest` GitHub repo. Render reads `render.yaml`
   (Free plan, Singapore, `npm install && npm run build`, `npm start`).
   *(Alternative: New → Web Service → same repo, plan Free, region
   Singapore, same build/start commands.)*
2. When prompted for the `sync: false` env vars, fill them **in Render**:
   - `DATABASE_URL` = the Neon connection string from step 1 (paste it
     directly into Render — this is the only place it should go).
   - `ADMIN_KEY` = a long random key you invent now, e.g. three random
     words + digits. **Write it down** — it is your Admin login key.
   - `ADMIN_NAME` = your name (optional).
   - Leave `AI_API_KEY` empty unless you have your own AI provider key.
3. **Apply / Create**. First deploy takes a few minutes. On first boot the
   server creates all tables and seeds the first Admin from `ADMIN_KEY`.
4. Open the Render URL (`https://ad-quest-….onrender.com`) and log in with
   your `ADMIN_KEY`. From the Admin dashboard you create Guru accounts
   (their Keys are generated by the server); Guru create Siswa & Pengawas.

### Render Free notes
- The service **sleeps after ~15 min idle**; the next open takes ~1 minute
  to wake. It never sleeps mid-exam once traffic is flowing — have the
  Guru/Pengawas open the app ±5 minutes before an exam starts.
- Free hours: 750/month per workspace — enough for one service.

## Local development

```bash
cp .env.example .env   # fill DATABASE_URL (Neon dev branch or local PG) + ADMIN_KEY
npm install
npm run migrate        # optional — the server also migrates on boot
npm run dev:server     # API on :3000
npm run dev            # client on :5173 (proxies /actions to :3000)
npm run typecheck
npm run build          # -> client/dist + dist-server/index.js
npm start              # production server (serves API + client)
```

Without `DATABASE_URL` the server refuses to start and prints exactly what
to set — by design.

## What was ported vs. gaps

Ported faithfully (verified end-to-end against a real Postgres):
Key login for Admin/Guru/Siswa/Pengawas; Admin user management & settings;
Guru exams/questions (manual + AI, AI points rebalanced to total **100**);
exam keys (check-then-start: *Pakai Key* validates without consuming,
**Siap Memulai Ujian** starts the timer and consumes the key); Siswa exam
runner with timer, autosave, submit, and anti-app-switch auto-lock
(visibility/blur/pagehide → account + attempt locked); Pengawas monitoring
grouped by subject + class with top lock notifications and unlock; results
inbox with per-question detail and essay grading; installable-app
(mobile/desktop) presentation from the artifact.

Gaps / differences from the artifact:
- The artifact's built-in Muse inference is gone by design. AI generation
  uses your `AI_API_KEY` provider, or the local template generator
  (quality is simpler than a real LLM — drafts are always editable).
- Data from the Muse artifact's database is **not** migrated by this repo
  (fresh Neon DB; accounts/exams are re-created by Admin/Guru). The seeded
  Admin key is whatever you set as `ADMIN_KEY` at deploy time.
- Session persistence on the client uses the same safe storage wrapper as
  the artifact (works in sandboxed iframes with an in-memory fallback).
- `npm run typecheck` is clean; the original's strict `noUnusedLocals`
  settings were relaxed in the port's single tsconfig.
